# 見積もり・請求 練習帳 仕様書

- 対象：見積もり → 請求書の流れを扱う小さな Web アプリ（アプリ名は「見積もり・請求 練習帳」）
- 位置づけ：テスト設計・テストケースの根拠となる文書。テストケースは、ここに書いた項目 ID（`S-...`）を引用する。
- このアプリはテストの練習のために作った題材である。実際の取引には使えない。
- 「【削る候補】」と書いた項目は、開発が間に合わない場合に作らないことがある。作らない場合はこの文書に「この版では作らない」と明記し、テスト設計からも外す。

## 0. 読み方

- 決まり 1 つにつき ID を 1 つ付けている。ID は `S-<分野>-<2 桁>` の形。
- 分野：`SCR` 画面 / `ST` 状態 / `INP` 入力 / `CALC` 計算 / `DATE` 日付 / `NUM` 番号 / `STO` 保存 / `DISP` 表示 / `OUT` この版で作らないもの
- 「できる」「できない」は、画面の操作としてできるかどうかを指す。

## 1. 画面（SCR）

| ID | 決まり |
|---|---|
| S-SCR-01 | 画面は 4 つ。画面の場所は URL の hash で表す：`#/` 見積もり一覧、`#/quotes/:id` 見積もり（作成・編集・詳細）、`#/invoices/:id` 請求書、`#/tests` テスト資料。 |
| S-SCR-02 | 見積もり一覧の列は、状態、見積もり番号、宛先、合計（税込）、発行日、有効期限。1 件が 1 行（`data-testid="quote-row"`）。 |
| S-SCR-03 | 一覧が空のとき、「見積もりはまだありません」を表示する。 |
| S-SCR-04 | 一覧の「新しい見積もり」ボタンで、新しい下書きを 1 件作り、その見積もり画面を開く。 |
| S-SCR-05 | 新しい下書きは、空の明細 1 行から始まる。その行は、品名が空、数量 `1`、単価が空、税率 10%。宛先と件名は空。 |
| S-SCR-06 | 見積もり画面には、宛先、件名、明細行、計算結果（税率ごとの対象額と税額、合計）、操作ボタンを表示する。 |
| S-SCR-07 | 見積もり画面から「一覧に戻る」リンクで一覧に戻れる。 |
| S-SCR-08 | 請求書画面は表示だけで、編集できない。項目は、請求書番号、元の見積もり番号、宛先、件名、明細、請求日、支払期限、税率ごとの対象額と税額、合計。 |
| S-SCR-09 | 存在しない見積もり ID・請求書 ID の URL（例：`#/quotes/xxx`）や、決まっていない hash（例：`#/foo`）を開くと、「見つかりません」と「一覧に戻る」リンクを表示する。 |
| S-SCR-10 | 全画面に「ポートフォリオ用の練習アプリです。実際の取引には使えません。」を表示する。 |
| S-SCR-11 | 画面の幅は PC と iPhone（375px 幅）の両方で使える。375px 幅で、ページ全体が横にスクロールしない。明細の表は、その枠の中で横にスクロールしてよい。 |
| S-SCR-12 | 「テスト資料」リンクは、全画面のヘッダーにある。押すと、テスト資料の画面（`#/tests`）を開く。 |
| S-SCR-13 | 明細行の右の「行を削除」ボタンで、その行を削除する。 |
| S-SCR-14 | 一覧は、新しく作った見積もりが上に来る並び（作成が新しい順）にする。 |
| S-SCR-15 | 下書きの一覧の行では、値のない見積もり番号、発行日、有効期限のセルに「—」を表示する。 |
| S-SCR-16 | 見積もり画面で「削除」を押し、確認で OK にすると、一覧（`#/`）に戻る。 |
| S-SCR-17 | 見積もり画面で「発行」を押すと、同じ見積もり画面にとどまり、状態が発行済みになる。 |
| S-SCR-18 | 見積もり画面で「請求書にする」を押すと、できた請求書の画面（`#/invoices/:id`）に移る。 |
| S-SCR-19 | hash のない URL（例：`/`）を開くと、見積もり一覧を表示する（`#/` と同じ）。 |
| S-SCR-20 | 一覧の各行で、宛先（空のときは「（宛先なし）」）は、その見積もりを開くリンクにする。 |
| S-SCR-21 | 全画面のヘッダーに、アプリ名「見積もり・請求 練習帳」をリンクとして表示する。押すと、見積もり一覧（`#/`）を開く。 |

## 2. 状態（ST）

```
下書き ─[発行]→ 発行済み ─[請求書にする]→ 請求済み
                   │
                   └ 有効期限を過ぎると「期限切れ」と表示し、請求書にできない
```

| ID | 決まり |
|---|---|
| S-ST-01 | 保存される状態は、下書き、発行済み、請求済みの 3 つ。新しい見積もりは下書きから始まる。 |
| S-ST-02 | 「期限切れ」は保存しない。発行済みの見積もりが、今日 > 有効期限 のとき、表示上だけ「期限切れ」とする。 |
| S-ST-03 | 状態の表示は、下書き / 発行済み / 期限切れ / 請求済み のいずれか（`data-testid="status"`）。 |
| S-ST-04 | 下書き：編集できる。削除できる。発行は S-INP-17 の条件を満たすときだけできる。請求書にはできない。 |
| S-ST-05 | 発行済み（期限内）：編集できない。削除できない。請求書にできる。 |
| S-ST-06 | 発行済み（期限切れ）：編集できない。削除できない。請求書にできない。 |
| S-ST-07 | 請求済み：編集できない。削除できない。請求書にできない。「請求書を見る」で、作った請求書を表示する。 |
| S-ST-08 | 「発行」を押すと、状態が下書きから発行済みになり、見積もり番号・発行日・有効期限が付く。 |
| S-ST-09 | 「請求書にする」を押すと、請求書が 1 枚でき、状態が発行済みから請求済みになる。請求書番号・請求日・支払期限が付く。 |
| S-ST-10 | 「削除」を押すと、確認ダイアログ（`window.confirm('この下書きを削除しますか？')`）を出す。OK なら下書きを削除する。キャンセルなら何も変えない。 |
| S-ST-11 | 一度進めた状態を戻す操作（発行の取り消しなど）は作らない。 |
| S-ST-12 | 「発行」や「請求書にする」を続けて何度押しても、番号は 1 つしか進まず、請求書は 1 枚しかできない。 |
| S-ST-13 | 状態ごとに、次の手順のボタンを表示する。下書き →「発行」「削除」。発行済み（期限内）→「請求書にする」。期限切れ → 押せない（灰色）「請求書にする」。請求済み →「請求書を見る」。状態が進むと、表示するボタンが変わる（そのため、連打しても同じ操作は 2 回行われない）。 |
| S-ST-14 | S-ST-13 でその状態に表示するボタンが押せないときは、消さずに灰色で表示し、理由をそのそばに出す。下書きに誤りがあるとき、押せない「発行」のそばに「入力の誤りが N 件あります」を出す（詳細は S-INP-31）。期限切れのとき、押せない「請求書にする」のそばに「有効期限を過ぎたため、請求書にできません」を出す。 |
| S-ST-15 | 見積もり画面の状態を進めるボタン（「発行」「削除」「請求書にする」「請求書を見る」）のうち、その状態について S-ST-13 に書いていないものは、画面に出さない。他の画面のボタン（「新しい見積もり」「見本を入れる」など）には、この決まりは関係しない。 |
| S-ST-17 | 明細の編集ボタン（「明細を追加」「値引きを追加」「行を削除」）は、下書きでだけ表示する。発行済み、期限切れ、請求済みでは画面に出さない。 |
| S-ST-16 | 発行済み、期限切れ、請求済みの見積もり画面では、見積もりの項目（宛先、件名、明細）を文字として表示する。入力欄は出さない。 |
| S-ST-18 | 状態を進めるボタンをダブルクリック（短い間に 2 回続けて押す）しても、行われる操作は押した 1 つだけ。2 回目の押下で、次の状態のボタン（「発行」の次の「請求書にする」など）が押されてはならない。 |

## 3. 入力（INP）

### 3.1 入力の決まり

| ID | 項目 | 決まり |
|---|---|---|
| S-INP-01 | 宛先 | 必須。1〜50 文字。 |
| S-INP-02 | 件名 | 任意。0〜50 文字。 |
| S-INP-03 | 明細行の数 | 1〜20 行。値引き行も数に含む。 |
| S-INP-04 | 品名 | 必須。1〜40 文字。 |
| S-INP-05 | 数量 | 整数。1〜9,999。 |
| S-INP-06 | 単価（税抜） | 整数。0〜9,999,999 円。 |
| S-INP-07 | 税率 | 10% または 8%。明細行ごとに選ぶ。 |
| S-INP-08 | 値引き行 | 税率（10% / 8%）と金額（整数、1〜9,999,999 円）を入れる。合計からはマイナスとして扱う。 |
| S-INP-09 | 値引きの上限 | 税率ごとに、値引きの合計がその税率の明細の合計を超えてはいけない（税率ごとの対象額がマイナスにならない）。値引きの合計と明細の合計が同額なら誤りではない（対象額 0 円は許される）。同じ税率の明細が 1 行もないときは、その税率の明細の合計は 0 円として扱う。空や誤りの金額は 0 として数える（S-CALC-11）。 |
| S-INP-10 | 金額の入力 | 金額は税抜で入力する。税込での入力は受け付けない。 |

### 3.2 数値と文字の読み取り

| ID | 決まり |
|---|---|
| S-INP-11 | 数量・単価・値引き額の入力は、全角を半角にそろえ（NFKC 正規化）、前後の空白を取り除き、カンマをすべて取り除いたあと、数字だけならその整数として読み取る。 |
| S-INP-12 | 次の入力は、数値として誤りとする：小数（`1.5`）、マイナス（`-1`）、プラス記号（`+5`）、指数表記（`1e3`）、空、空白だけ、数字以外の文字。 |
| S-INP-13 | 文字数は、前後の空白を取り除いて数える。空白だけの入力は、空として扱う。 |
| S-INP-14 | 文字数は、見た目の 1 文字を 1 つと数える。例：`👨‍👩‍👧` は 1 文字。 |
| S-INP-32 | S-INP-11 で受け付ける入力の例：`１２` → 12、`1,000` → 1000、` 5 ` → 5、全角カンマ `１，０００` → 1000、全角空白で囲んだ `　5　` → 5、`007` → 7、`1,,0` → 10（カンマは位置にかかわらず取り除く）。 |
| S-INP-38 | 全角の空白（U+3000）も空白として扱う。文字の項目（宛先・件名・品名）では、前後の全角の空白も取り除いてから数える（S-INP-13）。全角の空白だけの入力は空として扱う。数値の項目でも、前後の全角の空白を取り除く（S-INP-11）。 |

### 3.3 入力チェックの文言と発行の条件

| ID | 対象 | 文言 |
|---|---|---|
| S-INP-15 | 宛先が空 | 宛先を入力してください |
| S-INP-16 | 宛先が 51 文字以上 | 宛先は50文字以内にしてください |
| S-INP-18 | 件名が 51 文字以上 | 件名は50文字以内にしてください |
| S-INP-19 | 品名が空 | 品名を入力してください |
| S-INP-20 | 品名が 41 文字以上 | 品名は40文字以内にしてください |
| S-INP-21 | 数量が誤り | 数量は1〜9,999の整数で入力してください |
| S-INP-22 | 単価が誤り | 単価は0〜9,999,999の整数で入力してください |
| S-INP-23 | 値引き額が誤り | 値引き額は1〜9,999,999の整数で入力してください |
| S-INP-24 | 明細が 0 行 | 明細は1行以上入れてください |
| S-INP-25 | 明細が 21 行以上 | 明細は20行までです |
| S-INP-26 | 値引きの超過 | 10%の値引きが、10%の明細の合計を超えています（8% のときは「8%の値引きが、8%の明細の合計を超えています」） |

| ID | 決まり |
|---|---|
| S-INP-17 | 「発行」は、S-INP-01〜S-INP-09 のすべてを満たしているときだけ押せる。1 つでも誤りがあれば押せない。 |
| S-INP-27 | 下書きは、入力の途中でも保存される（誤りがあっても保存される）。 |
| S-INP-28 | 各項目の誤りの文言（上の表）は、その項目に一度触れて離れた（blur した）あとに表示する。ただし、項目に属さない誤りの文言は例外で、blur を待たず常に表示する（S-INP-34）。 |
| S-INP-31 | 下書きに誤りがある間は、「入力の誤りが N 件あります」を常に表示する（押せない「発行」のそば）。項目に触れる前でも表示する。誤りがなくなると表示しない。 |
| S-INP-29 | 「明細を追加」と「値引きを追加」は、明細が 20 行（値引き行を含む）になると押せなくなる。 |
| S-INP-30 | 「明細を追加」は数量 `1`、税率 10% の空の明細行を足す。「値引きを追加」は、金額が空で税率 10% の値引き行を足す。 |
| S-INP-33 | N は、今その下書きに当てはまる誤りの文言の数。誤りのある項目は 1 つにつき 1 と数える（項目に触れたかどうかは関係しない）。これに、項目に属さない誤り（S-INP-24、S-INP-25、税率ごとの S-INP-26）を 1 つにつき 1 足す。 |
| S-INP-34 | 項目に属さない誤り（S-INP-24、S-INP-25、S-INP-26）の文言は、blur を待たず、誤りがある間は常に表示する。 |
| S-INP-35 | 例：新しい下書き（S-SCR-05）は、宛先が空、品名が空、単価が空なので、「入力の誤りが 3 件あります」を表示する。 |
| S-INP-36 | 最後の 1 行も「行を削除」で削除できる。削除すると明細は 0 行になり、S-INP-24 の誤りになる。 |
| S-INP-37 | S-INP-25（明細が 21 行以上）は、追加ボタンが 20 行で押せなくなる（S-INP-29）ため、画面の操作では起こらない。保存データに 21 行以上あるときだけ起こる。 |

## 4. 計算（CALC）

| ID | 決まり |
|---|---|
| S-CALC-01 | 行の金額 = 数量 × 単価。整数なので端数は出ない。 |
| S-CALC-02 | 税率ごとの対象額（税抜）= その税率の明細行の金額の合計 − その税率の値引きの合計。 |
| S-CALC-03 | 税率ごとの税額 = 対象額 × 税率 の 1 円未満を切り捨てた値。例：10% の税額 = `Math.floor(対象額 * 10 / 100)`。 |
| S-CALC-04 | 税額の端数処理は、税率ごとに 1 回だけ行う。行ごとには端数を処理しない（1 つの請求書につき、税率ごとに 1 回、という制度の考え方に合わせる）。 |
| S-CALC-05 | 税額は、対象額が 0 以下のときは 0 とする。 |
| S-CALC-06 | 合計（税込）= すべての税率の（対象額 + 税額）の合計。 |
| S-CALC-07 | 計算はすべて整数で行い、小数（浮動小数点）は使わない。 |
| S-CALC-08 | 最も大きくなる入力でも、正しい整数で計算できる。合計の上限は設けない。 |
| S-CALC-09 | 請求書は、請求書にした時点の見積もりの内容と計算結果をそのまま写し取る。その後、請求書の内容は変わらない。 |
| S-CALC-10 | 計算結果の欄は、対象額と税額を 10% と 8% の両方で常に表示する。明細がない税率は 0 円と表示する。 |
| S-CALC-11 | 数量、単価、値引き額が空または誤りのとき、計算ではその値を 0 として数える（S-INP-09 の値引きの超過の判定も同じ）。 |
| S-CALC-12 | 計算結果は、入力が途中でも常に表示する。新しい下書き（S-SCR-05）では、すべての金額が 0円 になる。一覧の「合計（税込）」も下書きに同じ決まりで計算した値を表示する。 |

計算の例（S-CALC-04）：

- 10% の明細「品名 A・数量 1・単価 19 円」と「品名 B・数量 1・単価 19 円」の 2 行。
- 税率ごとに 1 回で処理する（仕様どおり）：対象額 38 円、税額 `floor(38 × 10 / 100)` = `floor(3.8)` = 3 円、合計 41 円。
- 行ごとに処理した場合（仕様ではない）：各行の税額 `floor(1.9)` = 1 円、合計 2 円となり、合計は 40 円になる。この結果は誤りである。

最大の入力の例（S-CALC-08）：

- 10% の明細 20 行、すべて数量 9,999・単価 9,999,999 円。
- 1 行の金額は 99,989,990,001 円。対象額は 1,999,799,800,020 円。税額は 199,979,980,002 円。合計は 2,199,779,780,022 円。

## 5. 日付（DATE）

| ID | 決まり |
|---|---|
| S-DATE-01 | 日付はすべて日本時間（Asia/Tokyo）で決める。端末の時刻帯が日本以外でも、「今日」は日本時間の今日とする。 |
| S-DATE-02 | 発行日 = 「発行」を押した日。 |
| S-DATE-03 | 有効期限 = 発行日の 30 日後の日付。例：11/1 に発行 → 12/1。 |
| S-DATE-04 | 有効期限の当日までは、請求書にできる。 |
| S-DATE-05 | 有効期限の翌日からは、請求書にできない（期限切れ）。 |
| S-DATE-06 | 請求日 = 「請求書にする」を押した日。 |
| S-DATE-07 | 支払期限 = 請求日の翌月の末日。例：1/31 に請求 → 2/28（うるう年は 2/29）。 |
| S-DATE-08 | 12 月に請求したときの支払期限は、翌年の 1 月の末日。例：12/15 に請求 → 翌年の 1/31。 |
| S-DATE-09 | 日付の計算は、うるう年、月末、2 月、年またぎで正しい日付になる。例：2028-01-30 に発行 → 有効期限 2028-02-29。3/31 に請求 → 支払期限 4/30。1/31 に請求 → 支払期限 2/28（うるう年は 2/29）。 |
| S-DATE-10 | 日本時間の 23:59:59 は、その日の日付。日本時間の 00:00:00 は、翌日の日付。端末の時刻帯にかかわらず同じ（例：UTC の 2026-11-20 15:00:00 は日本時間の 2026-11-21 00:00:00）。 |

## 6. 番号（NUM）

| ID | 決まり |
|---|---|
| S-NUM-01 | 見積もり番号は、発行したときに `Q-0001` から順に付ける。 |
| S-NUM-02 | 下書きには見積もり番号を付けない。 |
| S-NUM-03 | 請求書番号は、請求書にしたときに `INV-0001` から順に付ける。 |
| S-NUM-04 | 番号は重複せず、欠番も出ない。下書きを削除しても欠番は出ない（番号を発行時に付けるため）。 |
| S-NUM-05 | 見積もりの番号と請求書の番号は、それぞれ別に数える。 |
| S-NUM-06 | 番号が 9999 を超えたら、桁が増える（`Q-10000`、`INV-10000`）。 |

## 7. 保存（STO）

| ID | 決まり |
|---|---|
| S-STO-01 | データはブラウザの中（localStorage）に保存する。ページを読み込み直しても、データは残る。 |
| S-STO-02 | 保存は、入力のたびに自動で行う。保存ボタンは作らない。 |
| S-STO-03 | 保存できないとき（容量不足、プライベートブラウズなど）でも、画面は止まらない。 |
| S-STO-04 | 保存できないとき、「保存できませんでした。」を出す（`role="alert"` の帯）。この表示は消さずに出し続ける。 |
| S-STO-05 | 保存できないときでも、入力した内容はメモリ上に残り、画面に表示され続ける。 |
| S-STO-06 | 【削る候補】一覧が空のときは、架空の会社の見本データを入れる「見本を入れる」ボタンを出す。押すと見本の見積もりが一覧に入る。 |
| S-STO-07 | 【削る候補】保存データが壊れていて読めないときは、「データを消して初めからやり直す」ボタンを出す。押すと保存データをすべて消して、空の一覧にする。 |

| S-STO-09 | 「データを消して初めからやり直す」は、番号の数え方も消す。そのあと最初に発行する見積もりは `Q-0001` になる。 |
| S-STO-10 | 【削る候補】「見本を入れる」で入る見本は、ちょうど 3 件：下書き 1 件、発行済み 1 件（発行日は今日）、請求済み 1 件（発行も請求も今日）。 |
| S-STO-11 | 【削る候補】見本の宛先は、すべて末尾が「（架空）」で終わる。 |
| S-STO-12 | 【削る候補】見本の明細には、10% の明細、8% の明細、値引き行が含まれる。 |

### 7.1 テストで使う取り決め

テストが、アプリの作りを読まずに保存データを用意・確認できるようにするための決まり。

| ID | 決まり |
|---|---|
| S-STO-13 | データは、ブラウザの localStorage の `mitsumori:v1` というキーに、JSON として保存する。 |
| S-STO-14 | JSON の形は次のとおり。入力した値は、利用者が打った文字列のまま持つ。`counters` は最後に使った番号（0 はまだ使っていない）。 |

```
{ "version": 1, "quotes": Quote[], "invoices": Invoice[], "counters": { "quote": number, "invoice": number } }

Quote   = { id, status: "draft"|"issued"|"invoiced", number: string|null, recipient, subject,
            lines: Line[], issuedOn: "YYYY-MM-DD"|null, validUntil: "YYYY-MM-DD"|null, invoiceId: string|null }
Line    = 明細 { id, kind: "item", name, quantity: string, unitPrice: string, taxRate: 10|8 }
        | 値引き { id, kind: "discount", amount: string, taxRate: 10|8 }
Invoice = { id, number, quoteId, quoteNumber, recipient, subject, lines: Line[],
            totals: { byRate: [{rate:10, base, tax}, {rate:8, base, tax}], total }, invoicedOn, dueOn }
```
